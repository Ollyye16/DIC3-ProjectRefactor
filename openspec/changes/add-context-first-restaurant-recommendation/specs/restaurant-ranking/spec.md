# Spec Delta

## Purpose

只對已驗證的方案結合情境相關性與交通負擔評分，以餐廳為單位產生最終排名（DESIGN.md §9；D002、D007、D008）。

## ADDED Requirements

### Requirement: 只對全 T 方案評分
系統 SHALL 只對組合狀態為 T 的方案計算情境與交通分數；F 方案排除，U 方案存入暫定區，MUST NOT 以扣分方式保留在已驗證排序中。

#### Scenario: 必要證據缺漏
- **WHEN** 某方案缺少營業時間證據
- **THEN** 該方案不進入已驗證排序，而是列入暫定區

### Requirement: 每間餐廳保留最佳已驗證方案
同一餐廳有多個已驗證方案時，系統 SHALL 只保留分數最高者參與餐廳間比較。

#### Scenario: 路線多的餐廳
- **WHEN** 餐廳 A 有三條已驗證路線
- **THEN** 排名中餐廳 A 只出現一次，附其最佳路線

### Requirement: 最多輸出三間不同餐廳
系統 SHALL 輸出最多三間不同餐廳；不足三間時回傳實際可支持的數量；同分 MUST 依固定 ID 排序。

#### Scenario: 只有兩間已驗證
- **WHEN** 只有兩間餐廳有已驗證方案
- **THEN** 輸出兩間，不以暫定項補足

### Requirement: 分數尺度與權重固定並版本化
各分數項 SHALL 使用比較前固定的 0–1 尺度，權重非負且總和為 1；MUST NOT 依每次候選集重新縮放。

#### Scenario: 不同候選集
- **WHEN** 同一餐廳與方案出現在兩次不同查詢的候選集中，其他輸入相同
- **THEN** 該方案的分數相同
