# Spec Delta

## Purpose

將使用者的自然語言用餐需求轉為固定欄位，讓後續召回、交通分析與條件查核使用一致且無歧義的輸入（DESIGN.md §3.1）。

## ADDED Requirements

### Requirement: 需求以固定欄位表示
系統 SHALL 將每次查詢解析為 `q = (c, o, t_dep, B, L_max, W_max, N_max, D_meal)`，並保留各欄位與原始語句的對應。

#### Scenario: 完整需求解析
- **WHEN** 使用者輸入「明晚 7 點從台中火車站出發，和朋友慶生，每人 600 元內」
- **THEN** 系統產生的需求包含情境 `c`（慶生、朋友）、出發位置 `o`、帶完整日期的 `t_dep`、預算 `B`（600、TWD、每人），且每個欄位可回溯到原句片段

### Requirement: 相對時間轉為帶日期的時刻
系統 SHALL 以 Asia/Taipei 時區將相對時間（如「今晚」「明天中午」）轉為完整日期與時刻後保存，MUST NOT 只保存相對詞。

#### Scenario: 相對時間
- **WHEN** 使用者於 2026-11-11 輸入「今晚 7 點」
- **THEN** `t_dep` 保存為 2026-11-11 19:00 Asia/Taipei

### Requirement: 關鍵欄位缺漏時補問
出發位置或出發日期時間不明時，系統 SHALL 向使用者補問，MUST NOT 自行假設。

#### Scenario: 缺出發地
- **WHEN** 需求未提供出發位置
- **THEN** 系統回傳補問，不進入召回與交通分析

### Requirement: 有歧義的單位不由模型猜定
預算是每人或整團、步行上限是單段或總量、距離或時間有歧義時，系統 SHALL 補問或解釋輸入問題，MUST NOT 由語言模型自行決定。

#### Scenario: 整團預算缺人數
- **WHEN** 使用者給整團預算但未提供人數，且需要換算每人金額
- **THEN** 系統補問人數，預算條件不以猜測值查核

#### Scenario: 無效單位
- **WHEN** 預算或步行上限的單位無法辨識
- **THEN** 系統回傳輸入錯誤說明
