# Spec Delta

## Purpose

依使用者的用餐情境召回有評論片段支持的候選餐廳，作為後續交通分析的搜尋範圍（DESIGN.md §9、§9.2；D002）。

## ADDED Requirements

### Requirement: 先召回情境候選再分析交通
系統 SHALL 先以情境召回形成候選餐廳，再對候選進行交通分析；MUST NOT 改找僅交通方便但無情境依據的餐廳。

#### Scenario: 無情境相符候選
- **WHEN** 召回結果為空
- **THEN** 系統回傳「無相符候選」的原因，不改以交通距離補足候選

### Requirement: 支援 BM25、向量與混合召回
系統 SHALL 支援 BM25、向量與混合三種召回方式；混合分數 MUST 採正規化後的加權融合，且權重、正規化方式、片段聚合與召回門檻 MUST 固定並版本化保存。

#### Scenario: 重現召回結果
- **WHEN** 以相同語料、相同版本參數執行同一查詢兩次
- **THEN** 兩次的候選集合與分數相同

### Requirement: 候選依餐廳去重
召回的片段 SHALL 依餐廳分組彙整支持片段與反證，每間餐廳在候選集合中只出現一次。

#### Scenario: 同店多片段
- **WHEN** 同一餐廳有五個片段命中「慶生」
- **THEN** 候選集合中該餐廳只出現一次，並附五個支持片段

### Requirement: 必要情境無支持片段判 U
使用者將情境指定為必要條件，而某候選沒有任何支持片段時，該條件 SHALL 判為 U，MUST NOT 判為 F。

#### Scenario: 指定必要情境
- **WHEN** 使用者要求「一定要適合約會」，候選餐廳沒有約會相關片段
- **THEN** 該候選的情境條件為 U
